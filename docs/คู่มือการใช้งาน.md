# คู่มือ StayDee เกาะล้าน

ระบบจองที่พักแบบ marketplace — ลูกค้าจองและโอนเงินให้เจ้าของรีสอร์ทโดยตรง

| หน้า | ไฟล์ | ใช้โดย |
|---|---|---|
| เว็บลูกค้า (ไทย / English / 中文) | `index.html` | ลูกค้า |
| ระบบเจ้าของรีสอร์ท | `owner.html` | เจ้าของรีสอร์ท |
| ผู้ดูแลแพลตฟอร์ม | `admin.html` | แอดมิน |
| นักพัฒนา | `dev.html` | ทีมพัฒนา |

---

## 1. สำหรับลูกค้า

### จองห้องพัก
1. เลือกวันเข้า-ออก จำนวนผู้เข้าพัก แล้วเลือกรีสอร์ท/ห้อง
2. กรอกชื่อ อีเมล เบอร์โทร (ใส่โค้ดส่วนลดได้ ถ้ามี)
3. เลือกวิธีชำระเงิน: **พร้อมเพย์**, **โอนบัญชี**, หรือ **จ่ายที่รีสอร์ท** (เฉพาะห้องที่เปิดให้จ่ายที่รีสอร์ท)
4. กดยืนยัน ระบบแสดง **หมายเลขการจอง (SD…)** และ **PIN 6 หลัก** — จดไว้ทั้งสองอย่าง

### โอนเงินและแนบสลิป
- จองแบบพร้อมเพย์/โอนบัญชี สถานะจะเป็น **รอชำระ** ให้โอนแล้ว **แนบสลิปในหน้าการจอง**
- เจ้าของรีสอร์ทตรวจสลิปแล้วกดรับชำระ สถานะจึงเป็น **ยืนยันแล้ว**
- ⏱ **ต้องแนบสลิปภายใน 24 ชั่วโมง** นับจากเวลาจอง ถ้าไม่แนบ ระบบจะยกเลิกการจองและคืนห้องให้อัตโนมัติ

### ค้นหา / ยกเลิกการจอง
- เมนู **การจองของฉัน** → ใส่หมายเลขการจอง + PIN (ถ้าล็อกอินไว้จะเห็นการจองของตัวเองโดยไม่ต้องใช้ PIN)
- ⚠ ใส่ PIN ผิด **5 ครั้ง** ระบบล็อกการจองนั้น **15 นาที** (เพื่อกันคนอื่นเดา PIN) รอแล้วลองใหม่
- ยกเลิกฟรีได้เฉพาะห้องที่เงื่อนไขเป็น "ยกเลิกฟรี" และก่อนวันเข้าพัก
- การจองเก่าที่ PIN 4 หลักยังใช้ได้ตามปกติ

## 2. สำหรับเจ้าของรีสอร์ท (`owner.html`)

เข้าสู่ระบบแล้วทำตามการ์ด **เริ่มต้นใช้งาน** (เพิ่มห้อง → ตั้งบัญชีรับเงิน → ตกแต่งหน้ารีสอร์ท)

| เมนู | ใช้ทำอะไร |
|---|---|
| การจอง | ดูรายการจอง กรองตามสถานะ ตรวจสลิป กดรับชำระ/ยกเลิก |
| ห้องพัก | เพิ่ม/แก้ห้อง ราคา จำนวนห้อง รูป |
| หน้ารีสอร์ท | รูป คำอธิบาย ลิงก์โซเชียล ลิงก์ประจำรีสอร์ท |
| ตารางห้องว่าง / ปิดห้อง | ดูห้องว่างรายวัน และปิดห้อง (เช่น ขายผ่านช่องทางอื่น) |
| บัญชีรับเงิน | ใส่เลขพร้อมเพย์ (เบอร์ 10 หลัก หรือเลขบัตร 13 หลัก) และ/หรือข้อมูลบัญชีธนาคาร — **ไม่ตั้งค่า ลูกค้าจะเลือกวิธีนั้นไม่ได้** |
| โค้ดส่วนลด | สร้างโค้ดของรีสอร์ทตัวเอง |
| ภาพรวมวันนี้ / แขกเข้า-ออก | งานประจำวัน |
| ยอดขาย / รายงานการเงิน / ส่งออก CSV | รายงาน |
| รีวิว / รายชื่อลูกค้า | ดูรีวิวและข้อมูลผู้จอง |

### ขั้นตอนตรวจสลิป
1. เมนู **การจอง** → กรองสถานะ **รอชำระ**
2. เปิดรายการ ดูสลิปที่ลูกค้าแนบ เทียบยอดกับบัญชีของคุณ
3. ตรงยอด → **รับชำระ** · ไม่ตรง → ติดต่อลูกค้าหรือยกเลิก
4. การจองที่ยังไม่มีสลิปเกิน 24 ชม. จะหายไปเอง (ถูกยกเลิกโดย "ระบบ (หมดเวลาชำระเงิน)")

## 3. สำหรับแอดมินแพลตฟอร์ม (`admin.html`)
- **การจองทั้งหมด / ที่พักทั้งหมด** ดูและแก้ได้ทุกรีสอร์ท
- **เจ้าของรีสอร์ท** อนุมัติ/ระงับผู้สมัครเป็นเจ้าของ
- **โค้ดส่วนลด**, **ภาพรวมและรายงาน**, **ลูกค้า**, **รีวิว**, **แจ้งเหตุฉุกเฉิน (SOS)**
- **สำรอง & กู้คืน** ส่งออก/นำเข้าข้อมูลทั้งระบบ — ควรสำรองก่อนแก้ข้อมูลจำนวนมาก

## 4. สำหรับนักพัฒนา (`dev.html`)
- **สไลด์ & รูปรีสอร์ท**, **ห้อง & รูปห้อง**, **รูปทั้งเว็บ** (โลโก้ แบนเนอร์ รูปโปรโมชั่น)
- **แก้หน้าเว็บ** ข้อความ/สี/รูป (หรือกดโหมดแก้ไขบนหน้าเว็บจริง)
- แบนเนอร์หน้าแรกและรูปโปรโมชั่นทำเป็นสไลด์หลายรูปได้ ตั้งระยะเวลาเปลี่ยนรูปได้

## 5. สำหรับผู้ดูแลระบบ: การติดตั้งและอัปเดต

### ติดตั้งเว็บ (GitHub Pages)
Settings → Pages → Source: `Deploy from a branch` → `main` / `(root)`
แล้วเพิ่ม URL เว็บใน Supabase → Authentication → URL Configuration (Site URL + Redirect URLs) เพื่อให้ล็อกอิน Google/Facebook ได้

### ฐานข้อมูล
- โครงสร้างอยู่ใน `supabase/migrations/` เรียงตามหมายเลข รันตามลำดับ (ตาราง `sd_*` ทั้งหมดเปิด RLS)
- Edge Function จัดการบัญชีทีมงานอยู่ที่ `supabase/functions/sd-staff`

### ติดตั้งการอัปเดตความปลอดภัยชุดล่าสุด (`20261011000016`)
สิ่งที่เพิ่ม:
1. **ล็อกการเดา PIN** — ผิด 5 ครั้งล็อก 15 นาทีต่อการจอง (ตาราง `sd_pin_attempts`)
2. **PIN ใหม่ 6 หลัก** (เดิม 4 หลัก)
3. **ยกเลิกอัตโนมัติ** การจองพร้อมเพย์/โอนที่ค้าง `pending` เกินกำหนดและยังไม่มีสลิป (ฟังก์ชัน `sd_expire_pending`)

ขั้นตอน:
1. รัน migration `20261011000016_staydee_pin_lockout_expiry.sql` (Supabase SQL Editor หรือ `supabase db push`)
2. อัปโหลดโค้ดหน้าเว็บ (`js/store.js`, `js/pages.js`, `*.html`) — **ต้องอัปคู่กัน** เพราะฟังก์ชันตรวจ PIN เปลี่ยนรูปแบบ error เป็น `{"error": "..."}`
3. ตรวจว่า cron ทำงาน:
   ```sql
   select jobname, schedule from cron.job where jobname = 'sd-expire-pending';
   ```
   ถ้าไม่มีผลลัพธ์ เปิด `pg_cron` ที่ Database → Extensions แล้วรัน:
   ```sql
   select cron.schedule('sd-expire-pending', '*/15 * * * *', 'select public.sd_expire_pending()');
   ```

### ปรับเวลาหมดอายุการชำระเงิน
ค่าเริ่มต้น 24 ชั่วโมง เปลี่ยนโดยเพิ่ม `pendingHours` ใน `sd_kv` คีย์ `flags`:
```sql
update sd_kv set value = value || '{"pendingHours": 12}' where key = 'flags';
```
ถ้าลูกค้าแนบสลิปแล้วแต่เจ้าของยังไม่กดอนุมัติ ระบบจะ **อนุมัติให้อัตโนมัติ** (สถานะยืนยันแล้ว + ถือว่าชำระแล้ว) เมื่อเกิน 72 ชั่วโมง (ค่าเริ่มต้น) เปลี่ยนโดยใช้ `slipPendingHours`:
```sql
update sd_kv set value = value || '{"slipPendingHours": 48}' where key = 'flags';
```

### ทดสอบหลังติดตั้ง
- ค้นหาการจองด้วย PIN ผิด 5 ครั้ง → ครั้งที่ 5 ต้องขึ้นข้อความล็อก 15 นาที และใส่ PIN ถูกในช่วงล็อกก็ยังเข้าไม่ได้
- ทดสอบการจองใหม่ → PIN ต้องเป็น 6 หลัก
- ทดสอบยกเลิกอัตโนมัติ: `select public.sd_expire_pending();` (คืนจำนวนที่ยกเลิก) กับการจองทดสอบที่ `createdAt` เกินกำหนด
- ปลดล็อกการจองด้วยมือ (กรณีลูกค้าขอ): `delete from sd_pin_attempts where id = 'SDxxxxxxxxx';`

## 6. แก้ปัญหาเบื้องต้น
| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| ลูกค้าเลือกพร้อมเพย์ไม่ได้ | เจ้าของยังไม่ตั้ง "บัญชีรับเงิน" |
| ค้นหาการจองแล้วขึ้น "ลองผิดหลายครั้ง" | ถูกล็อก 15 นาที หรือแอดมินลบแถวใน `sd_pin_attempts` |
| การจองหายไปเอง | ถูกยกเลิกเพราะเกินเวลาชำระและไม่มีสลิป ดูที่สถานะ "ยกเลิก" โดย "ระบบ (หมดเวลาชำระเงิน)" |
| ใช้งานไม่ได้หลังอัปเดต | ลืมอัปโหลดไฟล์หน้าเว็บคู่กับ migration หรือ browser cache เก่า (รีเฟรชแรง Ctrl+F5) |
| ปิดรับจองชั่วคราว | เปิด flag `maintenance` ใน `sd_kv` คีย์ `flags` |
